# 分阶段实施、测试与验收计划

每阶段完成前保持 `DRY_RUN=True`，并只在服务条款许可后考虑真实输入。每阶段的产物必须经版本控制和自动测试后才进入下一阶段。

|阶段|目标、文件与实施|关键技术点|测试、验收、常见问题与前置条件|
|---|---|---|---|
|0：方案确认|已完成本方案。产物：README、`docs/`、`training/README.md`。确认地图/窗口/键位/条款并冻结首个场景边界。|安全边界、坐标体系、可观测性优先。|验收：用户确认未决项与 Phase 1 范围。常见问题：把占位参数当实测值。前置：Windows 测试机与可合法测试的窗口。|
|1：窗口采集与最小调试画面|实现 `capture.py`、`debug_ui.py` 最小预览、`config.py`、`main.py`、`test_capture.py`。枚举窗口、客户区→ROI、MSS 帧、DPI、窗口状态和 ROI overlay；不实现输入。|客户区而非外框；DPI physical pixels；窗口移动复算；有界帧队列。|测试：移动、最小化、失焦、DPI 100/125% 和异常尺寸；保存截图。验收：UI 同时显示实际客户区/ROI，异常时无崩溃。常见问题：边框偏移、黑帧。前置：稳定 ROI 截图。|
|2：抽帧与数据制作|实现 `training/extract_frames.py`、`training/dataset.yaml`、`datasets/README.md`、分组划分工具与标注 QA。|基于会话分割；相邻帧去重；YOLO 归一化框；类别一致。|测试：抽帧计数、标签边界/类别校验、train/val/test 无会话泄漏。验收：三集合可读、每类有复审样本。常见问题：小 loot 漏标/误标、连续帧泄漏。前置：可追溯数据版本。|
|3：训练与评估|实现 `training/train.py`、`evaluate.py`、训练 README、`test_detector.py` 离线桩。训练 nano/small，记录配置/随机种子/显存，导出候选 `best.pt`。|CUDA 可用性检查；先调 batch 再调 imgsz；每类指标和困难样本。|测试：小数据 smoke train、独立 test 评估、CPU fallback 报清晰错误。验收：选择具备可接受 Precision/Recall 与延迟的版本（阈值由用户/实测定义）。常见问题：OOM、过拟合、类别不平衡。前置：锁定模型及阈值候选。|
|4：实时检测与检测 UI|实现 `detector.py`、叠加绘制、`test_detector.py`。实时载入模型，输出框/脚点/时间戳/耗时/确认帧；绝不发键。|最新帧优先；按类别阈值；平滑、过期检测、玩家漏检计数。|测试：录制回放和现场只读运行；对比标签/人工观察。验收：UI 正确显示三类、框、脚点、FPS 与推理耗时。常见问题：ROI 外目标、模型版本不匹配。前置：玩家/怪物检测稳定。|
|5：定位、选目标与普通移动（DRY_RUN）|实现 `target_selector.py`、`movement_manager.py`、`controller.py`（仅 dry run）、`state_machine.py` 子集和单测。|目标滞回；有限短脉冲计划；动作后重新检测；单一控制器。|测试：回放驱动 FSM、模拟时钟、断言“攻击前释放键”；验收：日志只给出有限 MOVE_LEFT/RIGHT 计划，无真实输入。常见问题：左右抖动、过期帧决策。前置：通过危险场景回放测试。|
|6：瞬移策略（先 DRY_RUN）|扩展 movement/FSM/controller 测试，实现方向→瞬移顺序、冷却、次数上限和 RELOCALIZE。|没有固定瞬移距离假设；每次后 settle + 视觉复位；与攻击/Buff 互斥。|测试：伪造冷却、失败、漏检、连续目标变化；验收：没有无限连续瞬移，超时安全退出。常见问题：键序、技能冷却、落点误判。前置：实测位移日志和用户确认键语义。|
|7：攻击 FSM（仍先 DRY_RUN）|扩展 `state_machine.py`、`controller.py`、单测；实现释放→稳定→攻击片段→清空确认。|确认帧、最大攻击时长、攻击/移动排他、超时重定位。|测试：怪物单帧漏检、清空、攻击超时、急停回放；验收：无单帧停攻和无按键冲突。常见问题：攻击特效造成检测降级。前置：攻击范围已标定。|
|8：Buff 调度|实现 `buff_scheduler.py`、UI 倒计时及单测。|`monotonic` 到期标志；FSM 授权；有限重试；绝不在主循环长 sleep。|测试：虚拟时钟、瞬移时到期、失败重试耗尽、急停。验收：倒计时准确、没有与攻击/瞬移并发。常见问题：wall clock 改变、饥饿。前置：Buff 合规性、键位、周期实测。|
|9：掉落物巡检与宠物验证|实现 `loot_manager.py`、队列 UI、单测。|候选去重、距离/停留、视觉消失与拾取确认分离、有限超时/重试。|测试：loot 漏检、未消失、重复框、队列超时；验收：每件有明确最终状态且不会无限移动。常见问题：宠物动画、loot 被遮挡。前置：loot 模型和宠物范围实测。|
|10：联调与稳定性|集成 `main.py`、全量测试、故障注入、性能记录和操作手册。|异常边界统一 `release_all_keys`；线程退出；资源/日志轮换。|测试：2+ 小时只读 soak、窗口移动/最小化/失焦、模型丢失、GPU OOM、急停；如条款允许才在受控场景逐项启用真实输入。验收：每次故障可记录且安全释放，性能达到用户定义的实时阈值。常见问题：内存增长、队列积压、热键焦点。前置：用户逐项签核风险。|

## 建议测试层次

1. **单元测试：** 配置校验、坐标转换、检测结果过滤、FSM 转换、按键仲裁、Buff 虚拟时钟、loot 生命周期；不依赖游戏。
2. **回放集成测试：** 以保存帧/检测 JSON 驱动状态机，断言动作日志和安全释放。
3. **只读现场测试：** 所有功能在 DRY_RUN 下观察 UI/日志。
4. **受控输入测试：** 仅在书面确认合规、独立测试账号/场景（如适用）和可见急停验证后，逐项启用，绝不一次全开。
